
# GDD Модуль: Интерактивный Верстак Бронника (Armor Crafter Workbench)

## 1. Общая концепция

Верстак бронника — это физический объект на станции, требующий от игрока тактильного взаимодействия. Итоговые характеристики созданной брони (Armor Class и HP) **не прописаны заранее**, а динамически собираются из характеристик тех материалов, которые игрок физически положил на стол.

## 2. Основные сущности системы

### А. Чертеж (Blueprint)

Чертеж сам по себе не имеет защитных статов. Это «выкройка».

* **Функция:** Указывает верстаку, какую *базовую сущность* спавнить, как она будет выглядеть (спрайт) и какие **зоны покрытия** (Coverage Zones) она будет иметь (например: `[Torso]`).

### Б. Материалы для крафта (Armor Materials)

Любой кусок хлама, металла или ткани в игре может стать материалом для брони, если ему добавить компонент `ArmorMaterialComponent`.

* **Soft Layer (Мягкие материалы):** Ткань, кевлар, кожа, синтетика. Задают прочность основы.
* **Hard Layer (Твердые материалы):** Сталь, титан, керамика, дорожные знаки. Задают класс пробития (AC) плит.

---

## 3. Игровой процесс (User Flow)

1. **Подготовка (Физика):** Игрок берет в руки Чертеж и кидает его на Верстак (клавиша `Q` / Drop). Затем игрок скидывает на Верстак стопки нужных материалов (например, ткань или сталь).
2. **Интерфейс (BUI):** Игрок кликает по Верстаку пустой рукой. Открывается окно интерфейса.
3. **Настройка сборки:** * Интерфейс считывает лежащий на столе чертеж и пишет: *«Выбран рецепт: Тяжелый бронежилет»*.
* В интерфейсе есть два выпадающих списка: **Внешний слой (Soft)** и **Бронеплиты (Hard)**.
* Игрок выбирает в этих списках материалы *из тех, что физически лежат сейчас на столе*.


4. **Старт:** Игрок нажимает кнопку **[СОБРАТЬ]**.
5. **Процесс (DoAfter):** Окно может закрыться, над персонажем появляется полоса загрузки (например, 15 секунд). Станок издает звуки работы. *Если игрок отойдет или получит стан — крафт прерывается.*
6. **Результат:** Полоса доходит до конца, материалы и чертеж исчезают (удаляются), на столе спавнится готовая кастомная броня.

---

## 4. Алгоритм генерации статов (Под капотом)

Когда процесс `DoAfter` успешно завершается, сервер выполняет следующий код:

1. Берет ID прототипа из Чертежа и спавнит пустую базовую сущность брони.
2. Читает `ArmorMaterialComponent` у предмета, выбранного для **Soft Layer**:
* Берет оттуда параметры `grantedDurability` и `grantedArmorClass`.
* Находит в новой броне компонент `LayeredArmor` и перезаписывает секцию `softLayer` этими цифрами.


3. Читает `ArmorMaterialComponent` у предмета, выбранного для **Hard Layer**:
* Аналогично перезаписывает секцию `hardLayer` (например, выставляет AC 5 и Durability 300, потому что это был Титан).


4. Зоны покрытия (`CoverageZones`) копируются в оба слоя напрямую из настроек Чертежа.
5. Вызывает `QueueDel()` для использованных материалов и чертежа.

## 5. Техническое задание для разработчиков (Robust.toolbox)

Для реализации потребуется написать три C#-системы и несколько компонентов:

### Компонент 1: `ArmorMaterialComponent`

Вешается на ресурсы (металл, ткань).

```csharp
[RegisterComponent]
public sealed class ArmorMaterialComponent : Component
{
    // Куда можно вставить этот материал: Soft, Hard или Both
    [DataField("layerType")]
    public ArmorLayerType LayerType = ArmorLayerType.Soft;

    [DataField("grantedArmorClass")]
    public int GrantedArmorClass = 0;

    [DataField("grantedDurability")]
    public float GrantedDurability = 100f;
}

```

### Компонент 2: `ArmorBlueprintComponent`

Вешается на бумажные чертежи.

```csharp
[RegisterComponent]
public sealed class ArmorBlueprintComponent : Component
{
    // ID сущности, которая появится в итоге
    [DataField("resultPrototype")]
    public string ResultPrototype = string.Empty;

    // Зоны, которые будет закрывать броня
    [DataField("coverageZones")]
    public List<TargetZone> CoverageZones = new();
}

```

### Компонент 3: `ArmorWorkbenchComponent`

Вешается на сам станок.

* Должен работать в связке с ванильной `ContainerManagerComponent`, чтобы хранить положенные на него предметы (Чертеж и Материалы).
* Требует создания кастомного состояния пользовательского интерфейса (`BoundUserInterfaceState`), которое будет отправлять на клиент списки содержимого контейнера, чтобы отрисовать выпадающие списки выбора.
* Использует `DoAfterSystem` для задержки создания предмета.

### UI Дизайн (BUI)

Окно должно быть минималистичным, в индустриальном стиле:

* **Текст:** "Статус: Ожидание ввода"
* **Слот чертежа:** [Имя чертежа из контейнера]
* **Слой 1 (Основа):** [Dropdown список доступных Soft-материалов на столе] *(Отображает прогноз: даст X ХП)*
* **Слой 2 (Плиты):** [Dropdown список доступных Hard-материалов на столе] *(Отображает прогноз: даст Y Класс Брони)*
* **Кнопка:** Большая красная кнопка [ЗАПУСК ПРЕССА]. (Неактивна, если не выбраны материалы).
