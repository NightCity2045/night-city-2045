# Game Design Document: Netrunning & Local Networks (Night City 2045)

## 1. Vision & Overview
В мире Night City 2045 (Time of the Red) глобальная Сеть разрушена вирусом R.A.B.I.D.S. Нетраннинг больше не является "сидением в кресле на другом конце города". Теперь это опасная работа "в поле", требующая физического доступа к локальным серверным узлам.

Данный документ описывает реализацию **Локальных Сетей**, генерируемых физическими серверами в реальном мире.

---

## 2. Физическая инфраструктура (Realspace)

### 2.1. NetServer (Локальный сервер)
Центральный хаб для генерации цифрового пространства. 
- **Entity ID**: `NetServerBase`
- **Роль**: Сканирует физическое окружение и создает "Цифровую Комнату" (Digital Room).
- **Питание**: Работает через систему **LogicPower**. Требует логической связи с АПС (APC) или ЛКП (LCP) через НВ-кабель (LV Wire).

### 2.2. Система питания (LogicPower)
Новая система подключений, заменяющая традиционные провода SS14 для конечных потребителей.
- **Инструмент**: Катушка НВ-провода (Wire Spool).
- **Механика**: Прямая логическая связь между `LogicPowerProvider` (Источник) и `LogicPowerReceiver` (Потребитель).
- **Интеграция**: Нагрузка автоматически передается в ванильный Power Solver (Pow3r), обеспечивая потребление энергии из батареи АПС.

---

## 3. Цифровое пространство (Networld)

### 3.1. Генерация (Map Loading)
При инициализации сервера загружается карта-шаблон:
- **Файл**: `/Maps/_NC/NET/core_node.yml`
- **Механика**: Используется `MapLoaderSystem` с флагом `InitializeMaps = true` для автоматической активации физики и скриптов в цифровом мире.

### 3.2. Архитектура уровней
- **Parenting**: Все цифровые объекты (Аватары, Узлы) должны иметь родителем **Grid Entity**, а не Map Entity. Это гарантирует совпадение координат `(0,0)` и корректную работу физики пола.
- **Окружение**: Цифровой мир по умолчанию имеет искусственную гравитацию и белое амбиентное освещение.

---

## 4. Сканирование и Маппинг (Device Mapping)

### 4.1. Алгоритм обнаружения
Сервер находит устройства в сети по следующему принципу:
1. Определяется `LinkedNetwork` сервера (через APC).
2. Сканируются все сущности в радиусе/сетке, имеющие тот же `LinkedNetwork`.
3. Фильтруются объекты с компонентами `DoorComponent` или `DeviceNetworkComponent`.

### 4.2. Цифровые узлы (Nodes)
Каждое найденное физическое устройство порождает виртуальный узел:
- **Прототип**: `NetDeviceNode`
- **Размещение**: Сетка 3x3 вокруг центра комнаты с шагом в 2 тайла для предотвращения наложения.
- **Связь**: Компонент `NetDeviceNodeComponent` хранит `EntityUid` физического устройства для обратного управления.

---

## 5. Геймплейные механики

### 5.1. Вход (HotSim)
Нетраннер использует разъем интерфейса для "погружения":
- Тело нетраннера падает в состояние стазиса/сна.
- В цифровой комнате спавнится `Avatar`.
- Камера игрока переключается на Аватара.

### 5.2. Взаимодействие
- **Инфо-панель**: При клике на узел открывается UI с информацией о физическом устройстве (название, статус).
- **Управление**: Кнопки в UI (например, "Toggle Door") отправляют события через сервер на физический объект.
- **Визуализация**: Используются Popup-сообщения для подтверждения действий ("SCAN COMPLETE", "DOOR TOGGLED").

---

## 6. Технические детали (ECS)

### Основные системы:
- `NetServerSystem`: Логика генерации сети, сканирование устройств.
- `HotSimSystem`: Переключение сознания игрока, управление Аватаром.
- `LogicPowerSystem`: Управление логическими связями питания.
- `NetGlobalSystem`: Управление Глобальной Сетью (Старая Сеть).

### Компоненты:
- `NetServerComponent`: Данные сервера (ссылка на грид, список узлов).
- `LogicPowerReceiverComponent`: Данные о логическом питании.
- `NetDeviceNodeComponent`: Ссылка на физический прототип в реальном мире.

---

## 7. Дорожная карта (Roadmap)
1. **Этап 1 (Текущий)**: Стабильный спавн узлов, синхронизация координат, LogicPower.
2. **Этап 2**: Реализация МЕТА-языка для написания скриптов автоматизации.
3. **Этап 3**: Cyberpsychosis — цена установки интерфейсов и риск при "черном льде".
4. **Этап 4**: Глобальная Сеть и взаимодействие между разными локальными узлами через инфо-шлюзы.
